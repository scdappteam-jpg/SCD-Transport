SCD Control Tower

แผนภาพกระบวนการปฏิบัติงานภาพรวม

เอกสารนี้แสดงภาพรวมการไหลของข้อมูลและงานปฏิบัติการ ตั้งแต่การรับข้อมูลจากไฟล์และอีเมล การเปิดใบงาน การติดตามรถและสถานะเอกสาร การปฏิบัติงานคลังและสนามบิน การเข้าถึงของลูกค้า ไปจนถึงรายงานผู้บริหารและงาน HR

Latest flow · 29 Aug 2026
Additional Formal Scope

สโคปเพิ่มเติมนี้ครอบคลุมการเพิ่มสถานะรถตั้งแต่การล็อกโลเคชัน การติดตามการมาถึงหน้าสนามบิน การตรวจความครบถ้วนของเอกสารก่อนเข้าพื้นที่ การทำงานร่วมกันระหว่าง CS และคนขับในขั้นตอนรับของ มุมมองสำหรับลูกค้าที่ต้องการติดตามงานในรูปแบบใกล้เคียง SCD และหน้าจอแสดงผลแจ้งเตือนบริเวณจุด WH

1. ข้อมูลเข้า Input channels
Admin Uploadนำเข้าไฟล์ CSV/XLSX จากหน้าเปิดใบงาน
n8n Gmailตรวจอีเมลทุก 30 นาที ดาวน์โหลดไฟล์แนบ แล้วส่งเข้า API
Load Plan Importรับ Consol/Flight plan สำหรับงานขาออก
2. ตรวจและเปิดงาน Validate & create jobs
ตรวจชนิดไฟล์SCD CSV, Pickup Report, Consol Planning, Load Plan
กันไฟล์ซ้ำตรวจ hash ก่อน import หากซ้ำจะข้ามอัตโนมัติ
สร้าง/อัปเดต Jobเปิด House ใหม่ หรืออัปเดตข้อมูลเดิมที่เปลี่ยน
Error Alertไฟล์อ่านไม่ได้หรือ format ไม่ตรงจะสร้างแจ้งเตือน
3. ควบคุมงาน Operations control
Dashboardภาพรวมจำนวนงาน สถานะ ความเสี่ยง และตัวชี้วัด
Order Trackingติดตาม House/AWB, flight, customer, เอกสาร, timeline
CS Queueรอยืนยันลูกค้าและตรวจสอบรายการที่ต้องอนุมัติ
Alertsรวมงานเสี่ยง ไฟล์เปลี่ยน เอกสารขาด และ error
4. ปฏิบัติการหน้างาน Vehicle tracking & pickup
ล็อกโลเคชันรถเริ่มติดตามรถจากตำแหน่งจริงของคนขับ เพื่อยืนยันจุดรับของและเส้นทาง
เพิ่มสถานะรถรับงาน, ออกไปรับของ, รับของแล้ว, มุ่งหน้าสนามบิน, ถึงหน้าสนามบิน
CS & Driver HandoffCS ยืนยันข้อมูลรับของกับลูกค้า และคนขับยืนยันรับสินค้า เวลา รูปภาพ และตำแหน่ง
Pickup Exceptionแจ้งเตือนกรณีรถออกนอกเส้นทาง รับของล่าช้า หรือหลักฐานรับของไม่ครบ
5. จุดสนามบินและเอกสาร Airport readiness
Airport Arrivalบันทึกเวลาที่รถมาถึงหน้าสนามบินและเตรียมเข้าสู่ขั้นตอนคลัง
Document Readinessตรวจ Cargo, Permit, Manifest, Security และ Airline document ให้ครบถ้วน
Preparation Tagsแท็กสถานะความพร้อมของแต่ละส่วน เช่น เอกสารครบ, รอ CS, รอคนขับ, รอคลัง
Ready for WHเมื่อข้อมูลและเอกสารพร้อม ระบบส่งต่อสถานะให้ WH ดำเนินการตามลำดับ
6. ปฏิบัติการคลังและสนามบิน WH & terminal operations
Inbound WH3รับเข้าคลัง วาง Location และย้ายพื้นที่จัดเก็บ
Groupingจัดกลุ่ม House เลือก driver และออก Cargo/CTF
WH Display Alertหน้าจอจุด WH แจ้งเตือนรถใกล้ถึง งานเร่ง เอกสารขาด และรายการที่ต้องตรวจสอบ
Terminalส่งออกไป TG, TG Inter, BFS และติดตาม SLA
7. ขาออกและเอกสาร Outbound & documents
Load Plan Compareเทียบแผนเก่ากับแผนใหม่ เห็นรายการเพิ่ม/ลบ/เปลี่ยน
Confirm Load Planยืนยันแผนโหลดและผูกกับงานในระบบ
Outbound Openเปิดใบขาออกและส่งต่อ Terminal
Billingตรวจเอกสาร สร้าง invoice และติดตาม due date
Cargo Historyเก็บประวัติใบ Cargo และการวางบิล
8. มุมมองลูกค้า Customer access
Customer Portalลูกค้าดูสถานะงานของตนเองในรูปแบบใกล้เคียง SCD แต่จำกัดสิทธิ์ตามบัญชีผู้ใช้
Pre-arrival Viewลูกค้าเห็นรายการที่กำลังเตรียมเข้ากระบวนการ เช่น งานรอรับของและงานใกล้ถึงสนามบิน
Required Actionsแจ้งรายการที่ลูกค้าต้องเตรียมหรือยืนยัน เช่น เอกสารประกอบและเวลารับของ
Customer Notificationส่งแจ้งเตือนเมื่อสถานะสำคัญเปลี่ยน เช่น รับของแล้ว ถึงสนามบิน หรือเอกสารครบ
9. กำลังคนและ HR People operations
Attendanceเช็คอิน/เช็คเอาต์ GPS รูปภาพ และ timeline เริ่ม-จบ
Operations Mapดูตำแหน่งพนักงานและคนที่ยังไม่ผูกกลุ่มงาน
Leave Requestยื่นลา แสดงโควตา และอนุมัติ 2 ขั้น
OT Requestขอโอทีล่วงหน้า จ่ายตามจริงแต่ไม่เกินอนุมัติ
HR Exportปิดรอบเดือนและ export สรุปวันลา/OT
10. รายงานผู้บริหาร Executive view
Executive Dashboardรวมสถานะงาน งานเสี่ยง เอกสาร กำลังคน และ readiness
Import Historyดูไฟล์ที่นำเข้า งานใหม่ งานเปลี่ยน และไฟล์ที่ถูกข้าม
Monthly Summaryสรุปงาน Billing Attendance Leave และ OT สำหรับติดตามผล
แหล่งข้อมูลหลัก Admin upload, n8n Gmail, Load Plan import เป็นทางเข้าหลักของข้อมูลปฏิบัติการ
จุดควบคุมกลาง Job/House เป็นข้อมูลกลางที่เชื่อม Tracking, รถ, เอกสาร, WH3, Grouping, Terminal และ Billing
ระบบแจ้งเตือน Alert ถูกสร้างจากไฟล์เปลี่ยน, error, งานเสี่ยง, เอกสารขาด, รถใกล้ถึง WH และสถานะสำคัญ
มุมมองลูกค้า ลูกค้าเข้าถึงข้อมูลเฉพาะงานของตนเอง เห็นสถานะเตรียมเข้า รับของ ถึงสนามบิน เอกสาร และแจ้งเตือนที่เกี่ยวข้อง
ส่วนที่ต้องต่อจริง HR ตอนนี้เป็น flow หน้าจอ/localStorage หากใช้งานหลายคนควรย้ายเข้า backend/database
