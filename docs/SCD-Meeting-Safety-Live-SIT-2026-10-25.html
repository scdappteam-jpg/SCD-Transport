1. ผลรวมและขอบเขต

Automated tests ผ่าน 246 รายการ TypeScript และ production build ผ่าน ส่วน lint ของโค้ดส่วนเพิ่มผ่าน แต่ lint ทั้งโครงการยังมีข้อผิดพลาดเดิม 4 จุด/คำเตือนเดิม 3 จุดตามเอกสารก่อน deploy

Live API checks ผ่าน 84 รายการ รวมการเตรียมยูสทดสอบ การอ่าน baseline และกรณีปฏิเสธที่คาดไว้ การตรวจเหล่านี้เป็นการเรียก API บน production พร้อมอ่านผลกลับ ไม่ได้หมายถึงกดทุกขั้นผ่านกล้องโทรศัพท์จริง รายการที่ลองขณะเตรียมสคริปต์และหยุดก่อนสร้างงานไม่ได้ถือเป็นผลยืนยัน workflow

2. แยกข้อมูลจริงกับหลักฐานจำลอง

  • สิ่งที่ตรวจบนระบบจริง: API ที่ scd-transport.onrender.com, ฐานข้อมูล production ของเลข SIT, scanner ที่ deploy จริง, ไฟล์หลักฐานที่บันทึก/เปิดกลับได้ และรูปหน้าจอเว็บจริง
  • สิ่งที่จำลอง: สินค้า 5 CTN, โรงงาน, รถ SIT-ONLY, ชื่อติดต่อ/เบอร์ 0000000000, รูป Cargo/ท้ายรถ/ใบตรวจปล่อย, ลายเซ็นผู้ตรวจ/ผู้รับ, บาร์โค้ด Code128 และพิกัด 13.1,100.1 ทั้งหมดติดคำว่า SIT ONLY ไม่ใช่หลักฐานหน้างานจริง
  • พิกัดจำลอง: ใช้ใน payload ที่มี simulation=true เฉพาะ House SIT ที่มอบหมายให้ยูสนั้น ไม่บันทึกเป็นจุด WH3 และไม่สร้างการเช็กอินเข้างานจริง
  • เวลาในรายงาน: เป็นเวลาที่ระบบ production รับคำสั่ง SIT ไม่ใช่ระยะเวลาเดินรถจริง จึงห้ามใช้คำนวณ KPI หน้างาน
  • Dock: ตรวจลำดับ/ค่าประมาณ/ช่องที่เสนอเท่านั้น ไม่จ่ายหรือยึดช่อง Dock จริงให้รถจำลอง งาน L1 จัดเก็บเฉพาะช่องเสมือนที่มีชื่อ SIT ONLY

3. หลักฐานว่างานเดิมไม่เปลี่ยน

อ่าน baseline งานเดิม 3803 งาน ก่อนสร้าง SIT แล้วเทียบหลังจบ ตรวจเลขอ้างอิง ลูกค้า จำนวน/หน่วย Invoice ผู้ติดต่อ CS สถานะคนขับ รถ Flight ช่องเก็บ ยอดรับ เวลาใน workflow และ QA ผลพบงานเดิมเปลี่ยน 0 งาน และมีงานใหม่เพิ่มเฉพาะ SIT 3 เลขข้างต้น

SHA-256 ของข้อมูลธุรกิจงานเดิมก่อน: b054557ed08b67eb0967ca6919c3cc3a12d056caed11186acc48420f74d47fba
หลัง: b054557ed08b67eb0967ca6919c3cc3a12d056caed11186acc48420f74d47fba

จุดเช็กอินเดิมไม่เปลี่ยน ผู้ใช้/บทบาทเดิมไม่เปลี่ยน ช่อง Dock จริงและรายการคิวเดิมไม่เปลี่ยน การเปรียบเทียบนี้ครอบคลุมฟิลด์ธุรกิจที่ระบุ ไม่รวมค่าคำนวณตามนาฬิกา เช่น นาทีเหลือก่อน Flight หรือ activity log ของการทดสอบซึ่งเพิ่มได้ตามปกติ

4. ขั้นตอนที่ทดสอบและผลที่ควรได้

  1. Admin ระบุเฉพาะเลข SIT ในหน้า “กติกาคลังและ Driver” ปิดสวิตช์รวมและ Geofencing ไว้ ต้องไม่มีเลขงานจริงใน allowlist
  2. Driver ที่ยังไม่มี attendance เริ่มรอบแบบจริงต้องได้ 409 จากนั้นใช้ simulation=true เฉพาะ SIT ที่มอบหมายเพื่อจำลองรอบ ห้ามสร้าง attendance จริงแทนคนขับ
  3. ถึงจุดรับ → ลอง Load โดยไม่มีรูป/ลายเซ็น หรือขาดลายเซ็นผู้รับ ต้องได้ 422 และไม่โหลด
  4. ใส่ Checklist ทั้ง 10 ข้อ รูปสินค้า ใบ Cargo ลงชื่อ รูปท้ายรถ และลายเซ็นแยกสองฝ่าย → Load ได้ ต้องมีหลักฐาน 5 ไฟล์
  5. หลัง Load เปลี่ยนชื่อผู้รับ/หลักฐานแล้ว Complete ต้องได้ 409 เมื่อใช้หลักฐานชุดเดิมจึงผ่าน และไม่สร้าง 5 ไฟล์ซ้ำ
  6. ถึง WH3 → ยืนยันรับใบตรวจปล่อยโดยไม่มีภาพต้องได้ 422 → แนบภาพจำลองจึงผ่านและมีเวลารับเอกสาร
  7. WH ตรวจเอกสาร เปิดรับ ยืนยัน House และรับจำลอง 5 CTN → จัดเก็บก่อน QA ต้องได้ 409 และยังไม่ครอบครองช่อง
  8. ผู้ติดแท็กสแกน Single → ใช้ยูสเดิมอนุมัติ QA ต้องได้ 403 → บาร์โค้ดผิด House ต้องได้ 422 → ใช้รูปเดิมของผู้ติดแท็กต้องได้ 409
  9. QA คนละยูสสแกนภาพใหม่ถูก House → QA ผ่าน → จัดเก็บช่องเสมือน SITMEET25-01 ได้
  10. เปลี่ยนแท็ก → QA เดิมหมดผล → ย้ายต้องได้ 409 → ตรวจ QA revision ใหม่แล้วจึงย้ายในช่องเสมือนต่อได้
  11. Pair ต้องมีสองภาพ รูปเดียวหรือไฟล์ซ้ำต้องได้ 422 QA ต้องมีสองภาพใหม่ต่างจากผู้ติดแท็กจึงผ่าน
  12. Customer Direct ต้องเก็บประเภทแยก Invoice ขัดกันต้องได้ 409 คงของเดิมไว้ คิวที่เสนอใช้ D7 ส่วน L1 ใช้ D8–D11 หรือว่างถ้าไม่มีช่องเหมาะสม ไม่จองช่องจริงระหว่างเทส คงรายการคิว SIT ไว้ให้ตรวจย้อนหลัง ไม่ใช่คิวรถจริง
  13. Driver Time Log ค้นหาเลข SIT และติ๊ก “รวม SIT” ต้องเห็นเวลาที่มีจริงในระบบ ช่องที่ไม่เคยบันทึกต้องไม่ใช้เวลา createdAt แทน Driver ขอ Log คนอื่นต้องได้ 403
  14. เปิดไฟล์หลักฐาน SIT ทุกไฟล์กลับจาก storage ต้องได้ 200 และเป็น PNG จากนั้นตรวจ baseline และปิดโหมดทดสอบชั่วคราว

6. ข้อจำกัดและการทดสอบต่อ

  • ยังไม่ทดสอบ GPS/กล้องบนมือถือจริง ณ WH3 รอผู้ใช้ให้ Google Maps และรัศมีจึงค่อยตั้ง Geofencing
  • คงข้อมูล SIT และรายการคิว SIT L1/L3 ไว้สำหรับตรวจต่อ ไม่ควรเรียกรถหรือจ่าย Dock จริงจากสองรายการนี้
  • ยังไม่เปิดกติกากับงานจริงทั้งหมด การ deploy นี้ไม่ทำให้งานจริงเก่าต้องสแกน QA ใหม่พร้อมกัน
  • ตัวเลข 15 นาทีต่อคิวและลำดับ Flight มี unit tests และอ่านคิว production แยกเฉพาะ SIT แต่ไม่ทดสอบนำรถจริงไป Dock หรือขยับคิวจริง
  • การทดสอบ Load → Complete ทำต่อเนื่องด้วยหลักฐานชุดเดียว การกู้หน้าหลังปิดเบราว์เซอร์ระหว่างสองขั้นหรือออฟไลน์ยังไม่ได้รับรอง
  • ภาพสแกนถอดรหัสจริง แต่ภาพถูกสร้างขึ้นเพื่อ SIT ไม่พิสูจน์ว่ามีแท็กกายภาพสองใบหรือมีการรับสินค้าจริง
