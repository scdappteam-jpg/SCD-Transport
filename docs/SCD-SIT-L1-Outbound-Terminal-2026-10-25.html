2. ข้อมูลจริงกับหลักฐานจำลอง

  • สิ่งที่ทำบนระบบจริง: เรียก API production ด้วยยูส SIT ตามบทบาท บันทึกสถานะเฉพาะ L1 อ่านผลกลับ เปิดไฟล์จาก storage และเก็บภาพหน้าจอเว็บ production
  • สิ่งที่จำลอง: สินค้า 5 CTN รถและการเดินทาง เอกสาร EI/Permit/Cargo Transfer ภาพท้ายรถ ผลชั่ง X-Ray และ Loading Detail ไฟล์ทุกใบมีคำว่า SIT ONLY / SYNTHETIC ไม่ใช่หลักฐานหน้างานจริง
  • การสแกนตำแหน่ง: ทดสอบส่งรหัสฉลาก SIT ให้ API และตรวจผลถูก/ผิด ไม่ได้ทดสอบเครื่องยิงบาร์โค้ดหรือกล้อง ณ คลังจริง
  • เวลา: เป็นเวลา production รับคำสั่ง SIT ไม่ใช่ระยะเวลาปฏิบัติงานจริง ห้ามนำ Within30 หรือเวลารอไปใช้เป็น KPI คนขับจริง
  • เลข F: ชุดนี้ไม่มี F จริง จึงไม่ยืมเลข F ของงานจริงมาใช้ หน้าจออาจระบุ “ยังไม่มี F”
  • Geofencing: ปิดตลอดการทดสอบ ไม่ตั้งจุด WH3 และไม่มีการขอ GPS จริงหรือสร้างเช็กอินเข้างานของคนขับ
  • คิว Dock: คงรายการคิว SIT ที่เตรียมไว้จากรอบก่อนเพื่อดูย้อนหลัง ไม่จ่าย Dock จริงในรอบนี้ และไม่ใช้รายการ SIT เรียกรถจริง
  • การเงิน: จบที่ ReadyForBilling หมายถึงปิดขั้นตอน Terminal พร้อมส่งฝ่ายบัญชี ไม่ใช่ Billed ไม่สร้าง Invoice ไม่ส่งเมลเรียกเก็บ และไม่แก้ราคา/ต้นทุน

3. วิธีทำซ้ำในชุด SIT ใหม่

ห้ามกดเริ่มต้นใหม่ทับ L1 ที่ปิดแล้ว ให้ใช้ชุด SIT รอบใหม่หากต้องการเดินครบเส้นทางอีกครั้ง ส่วน L1 นี้ใช้ตรวจประวัติและไฟล์ย้อนหลัง ไม่ย้อนสถานะหรือแนบผลแทนของจริง

  1. Admin — ตรวจชุดก่อนเริ่ม: ค้น House ให้ตรง เปิด Timeline ตรวจ Stored, receipt 5 CTN, QA ผ่าน และยังไม่ปิด Terminal ตรวจว่ากติกาใหม่เปิดเฉพาะ SIT ส่วน Geofencing/สวิตช์รวมยังปิด บันทึก baseline งานอื่นและตำแหน่งคลังก่อนเปลี่ยนข้อมูล
  2. Admin — Master ของ SIT: ใช้ Master จำลองที่ไม่ซ้ำกับ House อื่น ตรวจหน้า Transport · Terminal · วางบิล เลือก Master/Flight แล้วต้องแสดงขอบเขต 1 House เป็น L1 เท่านั้น ห้ามนำ Master งานจริงมาใช้
  3. WH — ไปหน้า Mobile/Field Ops ขาออก: สแกนหรือเลือก House SIT → ตรวจ Location & Find Goods → ยืนยันพบสินค้า รหัสฉลากผิดต้องถูกปฏิเสธ ส่วนการกดเบิกก่อนยืนยันตำแหน่งต้องไม่ผ่าน
  4. WH — เบิกสินค้า: แนบ Outbound documents จำลองและกด “เบิกสินค้า / Pick” ต้องปล่อยเฉพาะช่องเสมือนของ SIT ตรวจว่ายอดรับเดิมยัง 5 CTN และไม่มีสินค้า House อื่นหลุดจากช่อง
  5. EI — อนุมัติ: ใช้ยูส SIT EI แนบรูปเอกสารเซ็นจำลองแล้ว EI Approve ถ้าไม่มีภาพต้องได้ 422 ห้ามเปลี่ยนบทบาท WH ให้เป็น EI แทน
  6. WH — เอกสารปล่อย: เลือก TG และตรวจรายการใบชั่งขาออก Security ตัวจริง Airline ตรงสาขา Permit และ Manifest/ตรวจยอด ใช้ไฟล์จำลองเฉพาะ SIT แล้ว Confirm WH3 documents หาก Checklist ขาดต้องไม่ผ่าน
  7. Transport — จัดรถขาออก: ระบุ SIT-OUT-L1, SIT UI / Driver, 4W-SIT และปลายทาง TG แล้ว “จองคิวรถ / Book” ข้อมูลนี้เป็นคิวในแอป ไม่ใช่การจอง AOT ภายนอก หากคำขอ timeout ให้รีเฟรชตรวจ aotBookedAt และทะเบียนก่อน ห้ามกดจองซ้ำโดยไม่ตรวจ
  8. Admin — อนุมัติคิว: ต้องจองก่อนจึงอนุมัติได้ ยูส Transport ไม่มีสิทธิ์อนุมัติ AOT เอง ตรวจ aotApprovedAt และรถส่ง Terminal ให้ตรง
  9. Transport — Cargo Transfer: ใส่ House เดียว วันที่/เวลา ต้นทาง WH3 ปลายทาง TG คนขับ ทะเบียน ประเภทรถ ผู้ปล่อย และ Permit จำลองก่อนออกฟอร์ม ไม่มี Permit ต้องไม่ผ่าน ฟอร์มไม่เพิ่ม House จริงเข้ากลุ่ม
  10. Transport — โหลดและออก WH3: ในหน้า Operations Control เลือกเฉพาะ House SIT แล้วเริ่มโหลดที่ WH3 แนบภาพท้ายรถจำลองและ “ออก WH3 ไป Terminal” ต้องได้ GoodsLoaded / EnRouteToTerminal ถ้าไม่มีภาพประตูปิดต้องไม่ผ่าน
  11. Terminal — รับคิวและสินค้า: เลือก Master จำลองและ SIT100 ยืนยันว่าแสดงขอบเขต 1 House จากนั้นรับคิวและรับสินค้า Terminal ระบบต้องมี goodsLoadedAt ก่อนรับสินค้า และต้องถึง Terminal ก่อนเริ่มชั่ง
  12. Terminal — ชั่ง: กดเริ่มชั่ง ใส่ 25 กก./Dimension จำลองและแนบภาพผลชั่ง → เสร็จพร้อมหลักฐาน น้ำหนักศูนย์ต้องไม่ผ่าน ดาวน์โหลดใบชั่งจาก App ได้โดยไม่สั่งพิมพ์ใบ Cargo หรือป้ายซ้ำ
  13. Terminal — X-Ray: กดเริ่ม X-Ray แล้ว Passed พร้อมภาพจำลอง ต้องมีเวลาเริ่ม/จบ ถ้าไม่แนบหลักฐานต้องไม่ผ่าน การ Load ก่อน X-Ray ผ่านต้องถูกบล็อก รอบนี้ไม่ได้ทดสอบ Hold/Re-X-Ray
  14. Terminal — Load และปิด: เริ่ม Load → แนบ Loading Detail จำลอง → เสร็จพร้อมหลักฐาน ต้องได้ ReadyForBilling และ terminalClosedAt หากไม่มีหลักฐานต้องไม่ผ่าน ห้ามออก Invoice จากการทดสอบนี้
  15. Transport — รับเอกสารคืน: แนบภาพ Cargo Transfer คืนที่มีคำว่าจำลอง แล้วบันทึกรับคืน ตรวจ cargoTransferReturnedAt จากนั้นยืนยันรถจำลองว่าง ต้องได้ Available การปิด Terminal ซ้ำต้องถูกปฏิเสธ ไม่เปลี่ยนเวลาปิดเดิม
  16. ตรวจท้ายรอบ: เปิดไฟล์ใหม่ทุกใบจาก storage ตรวจว่าเป็นไฟล์ SIT ตรงต้นฉบับ ตรวจงานอื่น/คลัง/คิว/ยูส/Geofencing เทียบ baseline แล้วปิด session ทดสอบชั่วคราว คงข้อมูล SIT ไว้ให้ตรวจย้อนหลัง

9. ประเด็นที่ยังต้องตรวจต่อ

  • คำขอจองคิวครั้งแรก timeout แม้บันทึกแล้ว ยังต้องตรวจความเสถียรการตอบกลับ ไม่สรุปว่าหน่วยความจำเต็มโดยไม่มีหลักฐาน และไม่มีการ deploy แก้ปัญหานี้ในรอบทดสอบ
  • ยังไม่ทดสอบรถ/กล้อง/พิกัด/เครื่องชั่ง/X-Ray/การโหลดเครื่องบินจริง และยังไม่เปิด Geofencing
  • ยังไม่ทดสอบ Hold/Re-X-Ray, เปลี่ยน Flight ระหว่างขาออก, เครือข่ายมือถือหลุดกลางแนบไฟล์ หรือกระบวนการวางบิล
  • Master และรถมีคำว่า SIT โดยตั้งใจ ไม่ใช่เลข AWB หรือทะเบียนที่ใช้ปฏิบัติงานจริง ข้อมูลนี้ต้องแยกจากรายงานปฏิบัติงานจริง

10. ไฟล์อ้างอิง

  • ผลคำขอทั้งหมด
  • ผล audit แยกงานจริง
  • สถานะสุดท้ายและรายการไฟล์
  • ผลเปิดไฟล์และ hash
  • ใบชั่ง Master จำลองที่สร้างจากระบบ
  • ผล SIT ขาเข้าและ deploy รอบก่อน
